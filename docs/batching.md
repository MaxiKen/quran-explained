## Author more than 50 verses per session

> "I need you to be generating contents for more than 50 verses at a time.
> And you just stop someplace good after 50 verses."

So each session produces **more than 50 verses**, and stops at a natural
boundary once past 50 — not at an arbitrary count, and not mid-argument.

**What "a good place" means.** Stop where the sources themselves mark a
boundary. The classical tafsīrs divide material into thematic units and say so
outright; Mujāhid's count of al-Baqarah's opening — four verses on the
believers, two on the disbelievers, thirteen on the hypocrites — is exactly
this kind of marker. A run that ends on a completed argument is a good place.
A run that ends halfway through a ruling or a narrative is not, even if the
verse count is right.

**Honest note on throughput, recorded so it is not rediscovered.** At the
writing rate measured so far (~4,700–5,400 finished words a session), 50 verses
at even the Tier C floor of 200 words is 10,000 words — beyond what one session
has produced. Sessions so far have delivered 4–7 verses. The instruction is
recorded as given; if a session cannot reach 50 verses without cutting quality
below the standard in [voice.md](voice.md), it should say so plainly in its
final message and in `docs/progress.md` rather than quietly shipping thin
commentary or silently authoring fewer.

Ways to move toward the target without lowering quality:
- work in contiguous ranges so reading is amortised across many verses
- stay at the **lower end of each tier's band** — the bands are ranges, and the
  floor is acceptable
- accept that Tier C verses (1,512 of them, 300–450 words) are where volume
  comes from, and that long Medinan sūrahs are dense with Tier A

## Push after every run

> "Include that everything is pushed after to remove after every run."

Commit **and** push at the end of every session, before writing the summary.
The workspace is not durable — it was reset to the original `main` commit once
already, stubbing every large `data/tafsir_*.json` down to 19 bytes and
deleting every authored file. Nothing survived locally; everything survived
because it had been pushed.

Never batch commits across sessions. Never leave authored JSON uncommitted at
the end of a turn.

If a push fails on authentication, say so in the final message and ask the
maintainer to reconnect GitHub in Arena — do not leave the work unpushed
without flagging it.

## Commit message convention

One commit per range authored, subject line naming the surah and verses:

```
Author chapter 2, verses 1-7: the opening thematic unit
```

The body should record the word counts against plan, the substantive material
carried, and the harness results. See `git log` for examples.
